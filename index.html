Kea2 — 基于性质的移动端功能测试框架 Kea2 — Practical Property-Based Testing for Mobile Apps

2025.05 – 至今Present
核心贡献者（Core Contributor） Core Contributor · 团队成果发表于 CCF-A FSE 2026 published at FSE 2026 (CCF-A)
ecnusse/Kea2 281 Stars · 60K+ Downloads

Kea2 融合 GUI 模糊测试与性质检查，解决传统脚本测试覆盖浅、无功能断言的痛点。已在 Markor、AnkiDroid、Amaze 等开源应用上发现 8 个未知缺陷，被微信、OPay、海尔、华为、小米、微信支付等企业采用；在微信 3 个版本中发现 41 个逃逸错误，被 OPay 作为 POS 机默认回归测试工具，并已集成至华为 DevEco Studio。 Kea2 fuses GUI fuzzing with property checking, fixing the shallow coverage and missing functional assertions of scripted testing. It found 8 previously unknown bugs in Markor, AnkiDroid and Amaze; adopted by WeChat, OPay, Haier, Huawei, Xiaomi and WeChat Pay; surfaced 41 escaped bugs across 3 WeChat releases; shipped as OPay's default POS regression tool and integrated into Huawei DevEco Studio.

个人贡献My Contributions

  • 静态选择器检查机制：在 Uiautomator2 基础上实现静态选择器检查，将移动端与 PC 的网络请求转化为本地静态组件树匹配，解决性能瓶颈，单次判定耗时从秒级降至毫秒级。 Static selector checking: built on Uiautomator2, converts device–PC network round-trips into local static widget-tree matching, cutting per-check latency from seconds to milliseconds.
  • 控件 / 树级别黑名单算法：在 Fastbot 基础上设计并实现控件级与树级黑名单，遍历过程中可屏蔽指定控件或区域并附加条件，将屏蔽粒度由传统 JSON 的「Activity 级」精准提升至「元素级」，生产实践中几乎覆盖所有屏蔽场景。 Widget / tree-level blacklisting: designed on top of Fastbot to block specific widgets or regions conditionally during traversal, refining blocking granularity from Activity-level JSON to element level — covering virtually every real-world scenario.
  • FBM Merge 模型合并：支持分布式多机并行测试，聚合 Fastbot 模型实现训练加速与模型共享，在不影响数据的前提下使模型文件平均体积减少约 90%，大幅降低存储开销。 FBM Merge: model merging for distributed multi-device parallel testing — aggregates Fastbot models for faster training and sharing, shrinking model files by ~90% on average with no data loss.

基于大模型的移动端 PBT 性质自动断言生成与修复系统 LLM-Driven Property Assertion Generation & Repair for Mobile PBT

2026.01 – 至今Present
已发表于 CCF-A 类会议 ASE 2026 Published at ASE 2026 (CCF-A)

针对 PBT 中性质断言依赖人工编写、自动生成易出错的痛点，设计利用 LLM 的「轨迹探索 → 自动性质推导 → 可执行测试生成 → 反馈修复」闭环，生成的断言可直接由 Kea2 框架加载执行，具备生产级落地能力。 Property assertions in PBT are hand-written and error-prone when auto-generated. I designed an LLM-driven closed loop — trajectory exploration → property inference → executable test generation → feedback-based repair — whose assertions load and run directly in Kea2, ready for production.

核心成果Key Results

  • 自动断言生成：从真实 GUI 交互轨迹自动推导可验证的 PBT 性质断言（功能前后置条件与交互流程），无需人工编写断言。 Automatic assertion generation: infers verifiable PBT properties (pre/post-conditions and interaction flows) from real GUI traces — no hand-written assertions.
  • 不精确断言自动修复：利用测试执行反馈让 LLM 自动扫描并迭代修正不稳定断言，成功修复 118/127 条（修复率 92.9%）。 Automatic repair of imprecise assertions: execution feedback drives the LLM to iteratively fix flaky assertions — 118/127 repaired (92.9%).
  • 规模评测：在 12 个真实开源 Android 应用上识别 1,210 个有效功能，自动生成 985 条性质断言，其中 912 条有效（有效率 92.6%），发现 25 个先前未知的功能性缺陷。 Large-scale evaluation: across 12 real open-source Android apps, identified 1,210 valid features, generated 985 property assertions (912 valid, 92.6%), and uncovered 25 previously unknown functional bugs.

HMAutoDroid：基于 LLM 的 HarmonyOS 自动化任务执行系统（GUI Agent） — LLM-Driven Task Automation for HarmonyOS (GUI Agent)

2025.01 – 2025.03
独立开发 · 基于 HMDroidbot 鸿蒙原生操控能力，引入并适配 AutoDroid 的 LLM 任务规划思想 Solo project · adapted AutoDroid's LLM task-planning onto HMDroidbot's native HarmonyOS control
majuzi123/HMAutoDroidbot

针对 HarmonyOS NEXT 早期自动化测试方案几乎空白、业界鲜见公开 LLM 驱动测试系统的现状，构建了面向鸿蒙的智能任务执行系统。 At a time when HarmonyOS NEXT had almost no automated testing tooling and no public LLM-driven test system existed, I built an intelligent task-execution system for HarmonyOS.

核心成果Key Results

  • 将 AutoDroid 的 Android 依赖全部替换为鸿蒙原生组件（HDC、hidumper、hmdriver2、hap 包管理），重构任务规划链路，使 LLM 能直接驱动鸿蒙 GUI 操作序列，绕过 Uiautomator2 / Appium 不可用限制。 Replaced every Android dependency of AutoDroid with native HarmonyOS components (HDC, hidumper, hmdriver2, HAP packaging) and rebuilt the planning pipeline so LLMs drive HarmonyOS GUI sequences directly — bypassing the unavailable Uiautomator2 / Appium stack.
  • 在 15 个 HarmonyOS 开源应用上执行 33 个跨模块测试任务：平均完成进度 79.66%，完全完成率 69.70%（23/33）；社交 / 消息通讯模块完全完成率 100%，低复杂度任务平均完成进度 93.10%。 Executed 33 cross-module tasks on 15 open-source HarmonyOS apps: 79.66% average task progress, 69.70% full completion (23/33); 100% full completion on social/messaging modules and 93.10% average progress on low-complexity tasks.
